## 项目目标

为“《文明 VI》式六边形地块 + 《群星》式可暂停实时运行 + AI 管理多个国家”的项目创建独立于大模型的世界状态底座。

当前版本仍是垂直切片，不是完整商业游戏或历史社会模拟。经济使用抽象资源单位；气象是物理启发的程序模型，**不是**完整的数值天气预报 / 全球大气环流模式（GCM）。海军、多军团、补给线、城市完整物资库存、城市服务设施、正式动画/音效仍待实现（围城与整城易主已在 v0.39 落地：封锁圈 → 每日成数 → 账满整座连地带人换手，但一座城同时只有一本账、只有一方围得，也不模拟援军解围与围城内粮价；v0.40 在其之上补了入侵边警、无守军缺口与都城吞并——红警与抵达日期都从引擎那份 `incoming_threats` 抄、落在无守军目标当日只按 `unopposed_loss_rate` 折兵且不保底 1 人、都城中心格账满就整国并入并抄走财政与粮草，但仍不模拟围城期间的围点打援与城内粮价；v0.43 把「过境敌土」从一句报价变成结算事实——敌境每格按 `movement.hostile_cost` 减速、走廊中途易主不再撤销订单、单条命令上限提到 60 点走不到的分段下令——并给练兵停摆公告按原因限速，但仍不模拟海军登陆、补给线与围城期间的粮价）。

## 快速启动

需要 Python 3.10 或以上，Windows / macOS / Linux 均可。

```bash
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements.txt pytest
.venv/Scripts/python worldgen.py --seed 2000 --output output_regenerated
.venv/Scripts/python simulate_climate.py --world output_regenerated/world_2000BCE.json --out output_regenerated/first_year_weather.json --seed 2000 --days 365
.venv/Scripts/python build_viewer.py
```

`output/world_2000BCE.json` 是保留的静态基线；重新生成请使用 `output_regenerated/`，不要无意覆盖它。macOS/Linux 将 `.venv/Scripts/python` 换成 `.venv/bin/python`。

- 双击打开 `output/viewer.html`，可离线交互查看各六边形地块、气候、自然灾害暴露、地形和国家。
- `output/world_map.png`：国家、河网与生物群系。
- `output/rainfall_map.png`：年均降水分布。
- `output/hazard_map.png`：相对自然灾害暴露指数。
- `output/world_2000BCE.json`：**完整初始世界状态**，后续系统从这里读取。
- `output/world_summary.json`：方便人类阅读的国家与统计信息。
- `output/first_year_weather.json`：首次 365 日逐日天气结算后汇总的12个月统计与示例事件。

`seed=2000` 是程序随机种子，恰好与公元前2000年的数字一致，但两者是独立参数。

### 随机世界与自定义国家

点击观察台顶部“新世界”打开开局面板。系统会**自动填入**四国默认国名、颜色、文明类型和人口，玩家不改也能直接生成；也可以增减到 2–12 国。国名、颜色、类型与人口均可逐项修改，种子留空时自动搜索公平地图。

- 每个国家初始核心固定为 16 格连通领土，避免海岸位置造成领土数量差。
- 新建世界使用通用 ID（A/B/C/D/E…）和默认名“国家A/B/C/D…”；固定基线世界仍保留 ELAR/MARIS/VAYR/SAHAR 作为历史剧本。AI、颜色、外交和城市系统都按实际国家列表动态处理。
- 生成器比较食物潜力、矿业潜力、灾害安全度和水源的变异系数，并搜索达到公平度阈值的种子。
- 生成结果保存到 `runs/worlds/world_custom_<seed>.json`，metadata 内记录公平度与生成参数。
- 这里的“公平”是地图资源指标上的可量化平衡，不声称能证明所有开局策略完全等价。

### 国家 AI 接口

点击“AI 席位”可逐国选择控制方式，无需修改源码或重启：

- Mock 规则 AI；
- 任意 OpenAI 兼容供应商，可填写 provider、model、base_url、超时、重试和输出上限；
- 密钥只填写**环境变量名**，页面仅显示是否已配置，永远不返回或保存密钥值。

HTTP 接口：

- `GET /api/agents`：读取四国当前控制器、模型和预算，不含密钥。
- `POST /api/agents`：`{country_id, settings}` 运行时切换单个国家控制器。
- `GET /api/setup`：读取自动填写的开局默认国家。
- `POST /api/new_game`：`{countries, seed}` 生成并切换到公平随机世界。

### 主菜单与存档

进入页面先显示主菜单，不再直接进入游戏：

- **继续游戏**：读取最近保存的存档。
- **载入存档**：独立列表页面，显示存档名、日期、游戏日、种子和四国名称，可载入或删除。
- **新建世界**：独立开局页面，自动填入默认四国，可修改名称、颜色、文明类型、人口和地图种子。
- **AI 席位**：进入世界后可逐国切换控制器。
- 游戏内按 `Esc` 或点击顶部“菜单”打开暂停菜单，提供继续、保存、载入、AI 席位和返回主菜单。
- 打开暂停菜单会冻结游戏；再按 `Esc` 或点击“继续”恢复。若打开前世界本来就处于暂停，关闭菜单不会擅自恢复时间。

新建世界时立即创建存档；之后每 30 个游戏日、返回菜单和关闭服务器时自动保存。存档保存在 `runs/saves/*.json`，元数据保存在同名 `.meta.json`。

存档接口：

- `GET /api/saves`：列出存档和当前存档 ID。
- `POST /api/saves`：`{operation:"save"|"load"|"delete", ...}`。

### 实时观察台

```bash
.venv/Scripts/python live_server.py --days 365 --speed 2 --open
```

观察台仅绑定 `127.0.0.1`，默认地址为 `http://127.0.0.1:8765/`。页面读取同一个 Python 规则引擎的实时状态，不是预录动画；可拖动/缩放地图、暂停、单步和切换速度。到达目标日后自动暂停并写入 `runs/live_dashboard.json`。该本地服务没有登录验证，不应绑定到公网地址。

地图提供六个数据驱动图层：卫星地形、政治、海拔、降水、资源分布和交通。资源层由生物群系、降水、河流、海拔计算粮食/金属/木材/石料/牧草潜力，并用不同方向的简单线条表示；交通层绘制河流和道路。道路不再使用图标，而是以都城或既有路网为起点，沿陆地六边形中心寻路到已建道路地块，绘制贯穿地块的连续线路；施工中的道路显示虚线，完成后并入道路网。

界面采用双模式布局：

- **观战**：左侧列出四国与实时建设进度，右侧记录 AI 决议、开工、完工、科研、交易和灾害。施工中的地块用进度环标记，完工后变为实心设施点，后续可直接替换为美术图标。
- **介入**：选择任意国家并接管，AI 会停止替该国决策，游戏自动暂停等待玩家；点击己方地块后，右侧显示建筑的科技要求、全国上限、造价和工期。点任意地块还会列出**站在这格上的军队**（不分归属），点敌方地块则额外给出本国每支待命军队攻打这一格的天数、成本、落脚格与到场系数，可以直接选军队下这道命令。国家面板还可以即时调整税率、研究领域、政策和劳动力预设，所有请求仍由规则引擎严格审核。
- 顶部资源条跟随当前选中/治理国家；时代名称与视觉组件分离，后续时代可以更换地图材质、色彩和边框主题，而不需要重写布局。

让 ELAR 使用 DeepSeek、其余三国保持 Mock：

```bash
.venv/Scripts/python live_server.py --days 180 --speed 2 --open \
  --models config/models.deepseek.json \
  --api-key-file "<本机密钥文件路径>" \
  --max-calls 2 --max-cost-usd 0.10
```

密钥文件只在启动时读取到进程环境变量，不写入配置或日志。页面顶部会显示 ELAR 的模型理由、动作、Token 和调用预算；模型失败时自动回退 `NO_OP`，其余国家不受影响。不传 `--models` 时仍运行全 Mock、零 API 费用。

`config/rules.json` 定义抽象资源、建筑、科研、政策、天气灾害与交易参数。`config/models.example.json` 展示四国混用 Mock 与 OpenAI 兼容模型的配置。复制为本地配置后，只在本机环境变量中设置密钥；不要把密钥写入 JSON、聊天或日志。真实付费调用必须同时显式设置 `--max-calls` 和 `--max-cost-usd`：

```bash
.venv/Scripts/python run_simulation.py run --days 1 --models config/models.local.json --max-calls 4 --max-cost-usd 0.20
```

没有密钥或预算时仍可全 Mock 运行；API 超时、限流、非法 JSON 会记录并回退 `NO_OP`，不会中断世界 Tick。`config/models.deepseek.json` 是已验收的 DeepSeek 配置（不含密钥）。真实验收共两次请求、4,137 Token；第二次 ELAR 的四个动作全部生效。长期 365/1,825 日正式实验仍全部使用 Mock。

## v0.3 城市与社会

- 城市等级按人口分为聚落、城邑、都城、大都会；住房容量限制人口增长速度。
- 粮食受仓容限制，粮仓和灌溉渠提高仓储与住房，避免无上限囤粮。
- 稳定度受税率、粮食安全、住房拥挤、城市化和公共建筑影响，并直接改变粮食、矿业和研究产出；过低会触发动荡损失。
- 建筑加入科技前置和全国上限：粮仓、工坊、书库、市场、神庙各一座，灌溉渠两座。建筑每天产生维护费。
- 矿山超过四座后总体效率递减，矿业专精可以富有，但不能无限线性增长。
- 每月可能发生宫廷腐败、丰收祭和工匠迁入，直接影响财政、稳定度和人口。
- 科技总等级推进时代：时代 I 青铜时代早期、时代 II 青铜时代盛期、时代 III 铁器时代。
- 可用 `SETTLE` 在相邻无主陆地建立前哨，动态扩展领土和国界；玩家与 AI 都使用同一规则。
- 三座奇观——大粮仓、大工坊、大书库——提供全国唯一的高级加成，并作为后期财政出口。

## v0.43 敌土真的减速、练兵不再唠叨、募兵经济重新定价

- **`hostile_cost` 从上线那天起就没生效过**：`core/movement.py::Movement.cost` 读 `state.get("owner")`，而唯一的生产者 `core/military.py::Military.movement()` 交出去的是 `hostile` 布尔——两个名字各说各话，于是「踏入别国一格多付 1.25 点」这条 v0.43 的核心规则只活在提示词、面板文案与 `march_daily` 的注释里，任何一次报价、任何一条路径都不因别国领土变贵。改读 `hostile`；`mapgen_custom.py::movement()` 不填这个键，正好是绘图器要的纯地理。新增 `test_hostile_soil_is_priced_into_every_road_that_crosses_it` 钉住三方恒等式：同一格、同一地形，**己方 = 中性价、无 actor = 中性价、别国 = 中性价 + `hostile_cost`**。此前没有任何一条测试读过这个键，所以键名错位没有让任何东西变红——这正是它能活一整批的原因。
- **走廊易主不再撤销订单，远征也走得到底**：`march_cancelled` 现在只剩一条触发路径（`军队已无力继续行军`）。三条测试跟着口径改写：`farthest_walkable_tile` 从已删除的 `Military._corridor` 换到目的地规则（落脚格须己方或无主），再用引擎自己的 `_road_plan` / `_expedition` 滤掉过境路线，好让计时类测试拿到的仍是一条不加价的路；`test_a_march_survives_the_corridor_turning_hostile`（原名 `...is_cancelled...`）断言订单存活并推进、当日不中止；`test_an_expedition_is_priced_but_never_walked` 改名 `test_an_expedition_walks_its_quoted_road_and_fights_on_arrival`，走完一整条横贯大陆的敌土路线、`army_arrived.fought` 为真、`battle.expedition` 为真。报价与结算从此是同一本账：远征真正付的价是会战里的 `expedition_factor`，不是行军途中的一纸劝退。
- **一座营为同一个原因每 60 天抱怨一次**：新增 `military.barracks.stall_notice_days`（60，`BARRACKS_KEYS` 与正整数闸门同步收进 `core/content.py`）与 `ArmyState.stall_notices`（逐 `(军队, 停摆码)` 记上一次公告日，`to_dict` / `from_dict` 往返不丢）。`Military._stall()` 仍然每天写 `army.stall`——面板、`barracks_report` 与 AI 观测照旧实时读到原因——但 `state.record("barracks_stalled")` 按码限速。必须限速的理由是实测：国库在日饷上下反复横跳时停摆码几乎天天翻转，旧规则「变化才公告」等价于「每天一条」。前端气泡同时把 `barracks_stalled` 拉黑（结算侧仍留全量事件，日记与回执不受影响）。`test_one_camp_complains_about_the_same_reason_once_per_cooldown` 用 12 次翻转喂进冷却窗，验它只响一次、冷却期满再响一次。
- **军饷、造价与养护同比例下调**：`barracks.daily_cost` 0.8 → **0.5**（−37.5%）、六个 `units.*.cost.treasury` × **0.625**（MILITIA 20 → 12.5、SIEGE 60 → 37.5）、六个 `units.*.upkeep_per_day` 下调约四成（MILITIA 0.03 → 0.018、SIEGE 0.06 → 0.036，贵→贱次序未变）。关键是让 `price ÷ daily_cost` 同缩 ⇒ **MILITIA 从空到成兵仍是约 25 日**，日历不动、每天那张账单变薄。动机取自用户自己的存档（seed 1730782755、第 4885 日）：三国里两国的净入是 0.62 与 1.64 财政/日，对面是 2.40 与 4.00 的日饷，而 `army_desertion` 全程为 0——卡死募兵的从来不是按兵计的工资，是按营计的天赋。
- **AI 建营改读流量，不再只看存量**：`agents/heuristic.py::_building_choice` 现在要求 `(已建 + 在建 + 1) 座营的日饷 ≤ (净入 − 养护) × 0.4`，再叠一条「国库仍付得起这堵墙」。旧口径是 `treasury ≥ cost + wage × 30`，即买得起砖、养不起兵——上面那批天天停摆的营就是这么立起来的。观测不需要新键（`last_economy.treasury_income` 与 `military_upkeep` 本来就在快照里），改的是判据。`tests/test_mass_battle.py` 的 `town()` 夹具因此补上这两个键，另加两条断言：「存量再厚也养不活第二座营」与「账算得过来的日子就该起营」。

## v0.39 围城与整城易主

- **城池中心格打的不是会战，是一本围城账**：`ATTACK` 的 `tile` 指到中心格就走 `_begin_siege` 而不是 `_battle`——军队必须已经站在中心格周围 `blockade_radius`（默认 1）格的封锁圈里，否则 `NOT_IN_RING`；一座城同时只有一方围得，被别国抢先就记一条 `siege_refused`。同一国第二支进圈是 `siege_joined`，把 `army_id` 追加进同一本账而不清零已有进度。会战照旧只能夺城域边缘格，所以「从边缘的城池打起」这条老规则没有变。
- **围城只有一个数字来源**：状态只存在被围方的 `CityState.siege = {attacker, armies, progress, started_day}` 里（围方不存副本，旧存档缺这个键读作 `null`），`core/state.py::siege_ledger(countries, defender, city, config, siege=None, at=None)` 派生 `open / armies / garrison / walls / share / progress / daily / days_left …` 共 18 个字段。日结算 `siege_daily`、按格报价 `tile_strikes`、AI 报价 `siege_opportunities` / `siege_marches`、`summary()`、`build_observation()`、面板与地图全部读这一个函数，没有任何一处自己算城破日；显式传 `siege=` 是「还没下单的预告账」（`open=false`），传 `at={army_id: 格}` 是「这支还在路上的军队假如落到这一格」的账。
- **成数与城破日**：`share = 圈内围方战力 /（围方战力 + 圈内守方防御 + 城墙 `wall_bonus` 1.6 分量）`，每天走 `daily_progress` 0.06 × 成数，账满 `fall_threshold` 1.0 即城破；稳定度**不进成数**（只在城破当日扣 `stability_loss` 8.0），双方每天各加 `exhaustion_per_day` 0.05 战争疲劳，`_peace_gate` 另按 `progress/threshold` 减 `peace_pressure` 10.0——城被啃得越满越早求和。基线（一支满编军队围一座边城）：无守军无墙 17 日、有城墙 20 日、圈内另有 8 支守军 34 日。
- **城破 = 整座易主**：`_fall_city` 把整片城域、建筑、**人口**一起交给胜方（人随城走，随后对双边 `sync_city_population`），城市对象从败方 `cities` 移进胜方，`managed_by` 归 `ai`，败方扣稳定度，缴到的建筑逐栋走 v0.37 那条 `_tribute` 立占领贡金账，最后合上这本围城账并记 `city_fallen`。解围三种码 `peace / ring_empty / captured` 都进 `siege_lifted` 并带上停在哪儿的进度。
- **城墙是内容表里的一栋建筑**：`buildings.WALL`（造价 60、工期 90 日、需 `bronze_metallurgy` 3 级、`on_city_center: true` 只能立在中心格，落错位置回 `NOT_CITY_CENTER`）；`core/content.py` 要求 `buildings` 里至少有一栋带 `on_city_center`，`military.siege` 必须恰好是那七个键——缺键、多键、坏值都是 `ContentError` 而不是 `KeyError`。
- **AI 会开围，也会开赴**：`agents/heuristic.py::_siege_orders` 在会战选路**之前**吃动作额度，先把已经站在圈里的军队翻成开围令，额度有剩才用 `Military.siege_marches` 把待命军队派去还没有人围着的墙；同一支军队不会被下两道令。新通道 `siege_marches` 只报**己方与无主走廊**里走得到的路线（`march_daily` 遇到「下一格已属他国」当日就中止行军，所以必须过境敌土的墙无论怎么定价都到不了，那种墙得先用会战夺一格城缘），并把落脚格用 `at=` 塞进同一本账，报出「行军 N 天 + 抵达后 M 日城破」。LLM 提示词教同一批键。

## v0.37 占领贡金

- **夺下带建筑的格子，换到的是对方财政的一小份**：`Military._battle` 在整格易主时把守方那栋建筑交给 `_tribute`，按 `military.capture_tribute_share`（2%）在守方名下记一笔贡金，为期 `capture_tribute_days`（180）天，到期自己停收。给的是年金而不是一次性掠夺，也不是把建筑搬走——建筑照旧被拆掉，贡金就是那份补偿，避免「白得一座粮仓 + 抽对方收入」双重得利。
- **抽的是缴付方自己的收入**：`core/state.py::tribute_base` 取该国当日 `tax_income + mine_income`（税 + 矿的毛收入，不看净数），`tribute_transfers` 把同一收缴方名下的多笔按 `capture_tribute_cap`（8%）封顶合并。经济越差交得越少，经济越好交得越多，比例始终是那 2%。日结算 `Military.tribute_daily()` 排在 `economy.settle_all` 之后、`march_daily` 之前，划拨额 `min(缴付方国库, 当日应付)`——国库空了就少划，不印新钱；`core/content.py` 用 `0 < share ≤ cap ≤ 0.15` 把「占比应当较小」钉成内容闸门，写进 0.3 直接拒绝载入。
- **道路不分归属，占了不抽**：`capture_tribute_exempt`（默认 `["ROAD"]`）是结算数据而不是硬编码分支，面板对免贡设施单独说明「这类设施不分归属，攻占它不会带来贡金」。
- **一份账，三处读**：结算、`summary()` 的 `country.tribute`、`build_observation()`、`GET /api/tile_strikes` 全部走同一个 `tribute_transfers`，所以格子上印的「夺下后 180 天内每日抽取其日收入的 2%（约 0.004/日）」就是当天真的划走的钱；`owed` 字段先告诉玩家对该国已计百分之几、离 8% 封顶还剩多少。

## v0.35 兵营规模与战场集结

- **兵营数量不再封顶**：`buildings.BARRACKS` 删掉 `max_per_country`，同一国连建 5 座、9 座都收；工坊等真正的唯一性建筑仍回报 `BUILDING_UNIQUE_LIMIT`，说明放开的是兵营而不是整张表。
- **每营定额固定**：一座在营兵营每天只练 `military.barracks.garrison_capacity`（4）支，练满就停工——进度停在 `price × progress_cap_ratio` 并回报 `GARRISON_LIMIT`，不会空烧军饷；全国到顶则回报 `ARMY_LIMIT`。
- **会师容量**：已建成兵营数 × 4；都城中心再固定加 4。两座营时普通格 8、都城 12，同一格多支驻军共用一个上限。兵营还按兵种检查本营名额。
- **会师派兵**：军事栏选源军和宿主，点「会师」，逐兵种调整数量。弹窗同时显示源军总兵力、目标剩余容量和最多可派数。只在确认时下令，抵达再按当时的容量结算。没有派走的兵和募兵进度留在原军，派空时保留墓碑。
- **上限随营数走**：`core/content.py::field_cap` = `max(maximum_strength, 在营兵营数 × garrison_capacity)`，即保底 12 支、4 座营 16 支、9 座营 36 支。同一个函数被 `state.summary()` 的 `army_cap` 与 `build_observation()` 共用，面板、AI、结算看到的是同一个数。
- **集结进结算**：`Military._mass` 按 `military.mass_radius`（1）格统计到场军队（在途的不算，下这道命令的那支抵达当日也不算在途），战力系数 = `minimum_mass_share` 保底 0.5 +（1 − 0.5）× 在场战力 / 全国战力；攻守双方同式，谁没到场谁贴保底。战损按 `_bleed_order` 先从在场军队扣，扣完再补后备，且不引入随机数。
- **报价先给集结**：`strike_options` 每条路线带 `mass` / `mass_share`，排序改成 `(days, -mass, army_id)`——同样快的两条里，先把兵聚齐的那条排前面；打不到的国家直接 `reachable=false, mass=0, mass_share=null`，不再给一个假系数。
- **AI 真的会聚兵**：`_strike_choice` 现在「先集结、再分兵」——主将还在行军时，同缺口的其余军队收到 `MARCH` 到集结格（`reinforce` / `rally`）；主将已抵达就立刻进攻，另一路（`companion`）必须挑不同缺口，免得两路挤在同一格白打。

## 物理与数值模型：已实现

1. **地形**：多尺度平滑噪声构造陆块；人工设定的地质造山带、山麓和海湾修饰高程。可重现，不是地壳板块动力学数值模拟。
2. **气候**：北纬梯度决定太阳辐射/平均气温基线；每升高约1000m使温度下降约6°C；陆海差异修正季节温差；基于纬度确定信风/西风的主要水汽输送方向；地形抬升增雨、内陆和背风坡减雨；每格输出12个月温度与降水气候态。
3. **水文**：优先洪水填洼法（Priority Flood），所有陆地六边形的下游路径均连接到海洋；按降水、粗略蒸散和入渗得到径流；地块汇水面积超过门槛时绘制主要河网。
4. **生态**：根据温度、降水与海拔划分荒漠、草原、森林、热带雨林、高山等粗粒度生物群系。
5. **灾害暴露**：洪涝、干旱、地震、火山、野火、热带气旋共6层。地震/火山集中在预设断裂带；洪涝依赖汇水面积、坡度和湿润程度；干旱依赖降水与热状况；野火依赖植被、干燥和温度；热带气旋只在低纬暖季沿海增加风险。
6. **逐日天气**：每月气候态叠加空间相关的随机天气异常，逐日生成气温、降雨、雪的状态；365日结算结果带月度国都天气与大陆范围内的示例灾害事件。

### 科学真实性边界

- **不是**ERA5再分析资料、ECMWF预报模式、CMIP6模拟、真实的流体动力学、河道水力学或完整板块构造。没有求解大气 Navier–Stokes 方程、原始方程或海气耦合。
- 降水量、地形形态、雨影强度、灾害指数的参数是**面向游戏的假设值**，没有用观测进行统计校准；六类灾害输出的0–1值是**相对暴露指数，不是年发生概率**。
- 灾害事件发生率为玩法实验用的启发式频率，不可用来估算真实地区风险或历史灾害。
- 没有冰川、地下水、水库、土壤侵蚀、气压场动力学、海平面变化或轨道岁差模型。
- 公元前2000年是政治与技术的起始设定，并没有直接套用现代地球同期气候；架空大陆无真实古气候观测。已知约4.2千年前的气候异常具有显著地域差异，不应给整个架空大陆强行套用单一全球干旱事件。
- 目前河流可确保**流向海洋**，但没有精细侵蚀/沉积、实测河网形态、河漫滩与河道流速。

## 对未来独立规则引擎的接口

程序产生的 `world_2000BCE.json` 中包含：

```text
metadata: 时间、地图尺寸、随机种子与假设
world_summary: 地理统计
polities: 四个初始国家、都城、核心地块、人口与科技

每个 tile:
  q,r / col,row              六边形坐标
  land, elevation_m, biome   地表类型
  monthly_temp_c[12]         逐月气候态
  monthly_precip_mm[12]      逐月降水气候态
  river, downstream          水文和河网连接
  hazards: {...}             六类相对灾害暴露
  owner_id                   初始主权控制
```

未来的规则引擎应当以**固定模拟Tick（一天）**更新世界；AI只提交行动，不直接篡改地形、天气、人口或库存。气候和事件运行可先在每日结算内独立推进；国家行为/产出在下一阶段实现。

## 开发优先级

1. **校准地质-气候-水文**：加入更合理的地壳板块、盆地、湖泊、积雪融水、气候环流与土壤模型；制定可量化合理性检查。
2. **人口/聚落/农业**：建立青铜时代农业产出、城市发展、仓储和运河水利；明确各国只控制核心聚居地。
3. **灾害反馈**：把天气/洪水/旱灾映射到作物、粮仓、迁徙、运输能力等世界状态变化，加入事件日志与恢复过程。
4. **实时调度**：按每个游戏日一个Tick推进；灾害触发即时通知，国家AI在较低频率决定长期战略。
5. **交互国家 AI**：便宜API先跑四国对照实验，并留出规则AI对照组。
